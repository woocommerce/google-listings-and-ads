# Asset Management

GLA registers and enqueues all frontend assets through `AssetsHandler`. Never call `wp_enqueue_script()` or `wp_enqueue_style()` directly.

## Asset Types

| Class | When to Use |
|---|---|
| `AdminScriptWithBuiltDependenciesAsset` | Webpack-compiled JS entry points (reads `{name}.asset.php`) |
| `AdminScriptAsset` | Simple JS with manually specified dependencies |
| `AdminStyleAsset` | CSS files for admin pages |
| `StyleAsset` | CSS for frontend (non-admin) |
| `ScriptAsset` | JS for frontend (non-admin) |

## Entry Points

Each webpack entry produces a corresponding asset in `js/build/`:

| Entry | Handle | Where Loaded |
|---|---|---|
| `index.js` | `gla-wp-admin-index` | Main admin UI (all GLA pages) |
| `product-attributes.js` | `gla-product-attributes` | Product edit screen |
| `blocks.js` | `gla-blocks` | Block editor |
| `gtag-events.js` | `gla-gtag-events` | All frontend pages (conversion tracking) |
| `notification-manager.js` | `gla-notification-manager` | Admin pages (push notifications) |
| `wp-dataviews-shim.js` | `gla-wp-dataviews-shim` | Loaded before `index.js` |
| `order-attribution.js` | `gla-order-attribution` | Order edit screen |
| `channel-visibility-meta-box.js` | `gla-channel-visibility-meta-box` | Product edit screen |

## Registering an Asset

Assets are defined in `src/Assets/` classes (e.g., `AdminAssets.php`, `AssetsHandler.php`) and registered via `AssetsHandler::register_many()`:

```php
// In Admin::get_assets() or a dedicated asset class
return [
    ( new AdminScriptWithBuiltDependenciesAsset(
        'gla-wp-admin-index',                // handle
        'js/build/index',                    // path relative to plugin root (no extension)
        function () {                        // optional: conditional enqueue
            return is_admin();
        }
    ) )->add_inline_script(
        'glaData',
        json_encode( $this->get_js_data() )  // PHP → JS data bridge
    ),
];
```

## PHP → JS Data Bridge

`Admin::get_assets()` calls `add_inline_script( 'glaData', json_encode([...]) )` on the main script handle. This data becomes available as `window.glaData` in JS:

```php
// In Admin::get_assets()
private function get_js_data(): array {
    return [
        'slug'                 => $this->get_slug(),
        'mcSetupComplete'      => $this->options->get_merchant_id() > 0,
        'adsSetupComplete'     => $this->options->get_ads_id() > 0,
        'mcSupportedLanguage'  => $this->mc_service->is_supported_language(),
        'mcSupportedCountry'   => $this->mc_service->is_supported_country(),
        'enableReports'        => true,
        'serviceBasedMerchant' => (bool) $this->options->get( OptionsInterface::IS_SERVICE_BASED_MERCHANT ),
        'dateFormat'           => get_option( 'date_format' ),
        'timeFormat'           => get_option( 'time_format' ),
        'initialWpData'        => [
            'version' => $this->get_version(),
            'mcId'    => $this->options->get_merchant_id(),
            'adsId'   => $this->options->get_ads_id(),
        ],
    ];
}
```

When adding a new `glaData` property, also update `global.glaData` in `js/src/tests/jest-unit.setup.js`.

## BuiltScriptDependencyArray

`AdminScriptWithBuiltDependenciesAsset` reads `js/build/{name}.asset.php` — generated by webpack — to automatically include the correct dependencies and content-hash version. Do not specify dependencies manually for built assets.
